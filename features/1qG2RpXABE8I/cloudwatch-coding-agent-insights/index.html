Amazon CloudWatch コーディングエージェントインサイトを発表、AIコーディングツールのROIを組織全体で可視化

FEAT AWS What's New · 2026/7/20
要約: AIコーディングエージェント（Claude Code・Codex・GitHub Copilot）の利用状況・コスト・生産性指標をCloudWatchで一元可視化。Claude apps gateway for AWS経由で追加実装なしにテレメトリを収集し、チーム・組織単位でROIを分析できる。

新機能の背景

企業がClaude Code・OpenAI Codex・GitHub CopilotなどのAIコーディングエージェントを組織全体に展開する動きが加速する中、「投資対効果（ROI）をどう測るか」が共通の課題となっています。従来は各エージェントの利用状況がバラバラに記録されるか、まったく可視化されておらず、エンジニアリングリーダーが次の問いに答えるのが困難でした。

  • どのチームにエージェントアクセスを拡大すれば最大の効果が得られるか
  • エージェントはどこで開発速度を向上させているか
  • 部門ごとのトークン予算をどう適切に設定するか

さらにスケール時の課題として、開発者ごとに個別のAPIキーを管理し、設定を手作業で配布し、コスト追跡を各チームの独自実装に委ねるという分散したガバナンス問題もありました。こうした背景から、OpenTelemetry（OTel）標準を活用した統合的な可視化基盤と、一元的なコントロールプレーンの必要性が高まっていました。

新機能の概要

Amazon CloudWatch コーディングエージェントインサイトは、AIコーディングツールが組織全体でどのような価値を生み出しているかをエンジニアリングリーダーが把握できるようにする、CloudWatchコンソール上のすぐに使えるダッシュボード群です。CloudWatchコンソールの GenAI Observability > Coding Agent Insights から直接アクセスでき、ダッシュボードの作成やインポートは不要で、エージェントがメトリクスを送信し始めると自動的に表示・集計されます。

主な機能

  • コスト・利用状況の追跡: トークン消費量、コスト、モデル別コスト対出力比などをorganization・department・team・cost center・ユーザーの各軸でスライス＆ダイス
  • 支出アラート: トークン請求の先行アラートを設定し、予算超過を事前に検知
  • 開発生産性との相関分析: エージェント採用率とコミットスループットやPRマージ速度の改善を相関させて効果測定
  • CSVエクスポート: 基礎データを独自分析用にエクスポート
  • PromQL対応: 標準のPromQLでクエリでき、独自ダッシュボードやアラームも構築可能

Claude apps gateway for AWSとの連携

Claude Codeの場合、Claude apps gateway for AWSを経由することで追加の実装なしにテレメトリを収集できます。このゲートウェイはclaudeバイナリに内包されたセルフホスト型のコントロールプレーンで、以下の5つを一元管理します。

  1. アイデンティティ: OIDC対応のIdP（Okta、Microsoft Entra ID、Google Workspace等）によるSSO認証
  2. ポリシー: 許可モデル、ツール権限、マネージド設定をIdPグループ単位で集中制御
  3. テレメトリ: OTLP/HTTPでCloudWatch・Datadog・Splunk・ClickHouseなど複数の宛先へファンアウト配信
  4. ルーティング: Amazon Bedrock・Claude Platform on AWS・Google Cloud・Microsoft Foundry・Anthropic APIへの振り分けとフェイルオーバー
  5. 支出上限: 組織・グループ・ユーザー単位の日次・週次・月次支出キャップ

ゲートウェイを経由した場合、各メトリクスにはIdPから取得したユーザー・チーム・組織の属性が付与されるため、Coding Agent Insightsダッシュボードがそのまま組織軸で集計されます。

使い方

Claude Code + Claude apps gatewayの設定手順

Claude Codeのエンタープライズ展開でコーディングエージェントインサイトを利用するには、以下の手順でClaude apps gatewayをデプロイし、CloudWatchへのテレメトリ送信を設定します。

前提条件の確認

要件 詳細
Claude Codeバージョン v2.1.195以降
アイデンティティプロバイダー OIDC対応（Okta、Microsoft Entra ID、Google Workspace、Keycloak、Dex等）
データベース PostgreSQL 14以降
モデルアップストリーム Amazon Bedrock、Claude Platform on AWS、Google Cloud等
TLS HTTPS証明書またはTLS終端イングレス
ランタイム 本番環境はLinux（macOSはローカル開発のみ）

ゲートウェイのデプロイ

  1. IdPにOAuthクライアントを登録し、リダイレクトURIを https://claude-gateway.your-domain/oauth/callback に設定する
  2. PostgreSQL 14以降のデータベースをプロビジョニングする（ゲートウェイが起動時にスキーママイグレーションを実行）
  3. gateway.yaml を作成し、Amazon Bedrockをアップストリームとする最小構成例を記述する
  4. claude gateway --config gateway.yaml でゲートウェイを起動する（DockerComposeまたはバイナリ直接起動）
  5. 認証フローを確認し、開発者のエンドツーエンド接続をテストする

開発者をゲートウェイに接続する

MDMや構成管理ツールで以下のマネージド設定を開発者マシンに配布します。

{
  "forceLoginMethod": "gateway",
  "forceLoginGatewayUrl": "https://claude-gateway.internal.example.com"
}

開発者は claude /login を実行し、ブラウザでのSSO認証を完了するだけで接続が完了します。

CloudWatchへのテレメトリ送信設定

gateway.yaml の telemetry セクションにCloudWatchをOTLP/HTTP配信先として追加します。ゲートウェイは各エクスポートにIdPから取得した開発者のアイデンティティを付与するため、ユーザー・チーム・組織属性付きでメトリクスがCloudWatchに到達します。詳細は設定リファレンスを参照してください。

ダッシュボードの確認

  1. CloudWatchコンソール（https://console.aws.amazon.com/cloudwatch/）を開く
  2. ナビゲーションペインで GenAI Observability > Coding Agent Insights を選択する
  3. コーディングエージェントのタブを選択する（メトリクスはエージェントがデータを送信してから数分以内に表示される）

その他エージェント（Codex・GitHub Copilot）の場合

ゲートウェイを使わず直接OTLPエンドポイントを設定する方式で、ベアラートークンまたはエンタープライズSSO経由でCloudWatchのネイティブOTLPメトリクスエンドポイントへ送信します。各エージェントのセットアップガイドはCoding Agent Insightsドキュメントを参照してください。

注意点

利用可能リージョン CloudWatch コーディングエージェントインサイトは、以下の3リージョンを除くすべてのAWSコマーシャルリージョンで利用可能です。

  • Middle East (UAE)
  • Middle East (Bahrain)
  • Israel (Tel Aviv)

料金 標準のCloudWatch OpenTelemetryメトリクス取り込み料金が適用されます。追加の機能料金はなく、メトリクスの量に応じた従量課金となります。詳細はCloudWatch料金ページを参照してください。

メトリクス属性の形式要件 Coding Agent Insightsダッシュボードは特定のメトリクスと属性の形式に依存しています。エージェントのネイティブOTelメトリクスはmodelやtoken_typeなどのコアディメンションを持ちますが、user.email・team.id・department・cost_center・organizationなどのアイデンティティおよび組織属性はOTelのリソース属性として送信する必要があります。メトリクス名を変更したり、アイデンティティ属性をリソースから外したりすると、ダッシュボードが正しく集計されない場合があります。セットアップガイドに従って設定することで、この形式が自動的に保たれます。

Claude apps gatewayのインフラ要件 Claude apps gatewayはセルフホスト型のため、ECS・EKS・EC2上でのコンテナ実行環境、内部Application Load Balancer、AWS Certificate ManagerによるTLS証明書、Amazon RDS for PostgreSQLが必要です。本番環境はLinuxのみサポートされ、macOSはローカル開発専用です。

Claude Codeの最低バージョン Claude apps gatewayを使用するにはClaude Code v2.1.195以降が必要です。それ以前のバージョンではゲートウェイ連携機能（/loginフローのゲートウェイ対応）が利用できません。
