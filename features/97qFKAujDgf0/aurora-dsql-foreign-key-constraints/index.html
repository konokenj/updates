Amazon Aurora DSQLが外部キー制約をサポート、分散SQLで参照整合性をデータベース層で宣言的に管理可能に

FEAT AWS What's New · 2026/8/27
要約: Aurora DSQLのサーバーレス分散SQL環境でFOREIGN KEY制約が利用可能に。新規・既存テーブルへの制約追加、CASCADE／SET NULL等の参照アクション、DEFERRABLE制約をサポート。ロックを使わない楽観的並行制御でマルチリージョン環境の参照整合性を保証。Aurora DSQL提供の全AWSリージョンで利用可能。

新機能の背景

Aurora DSQL はサーバーレス・分散型の SQL データベースであり、PostgreSQL 互換性とアクティブ/アクティブのマルチリージョン可用性を兼ね備えています。しかしこれまで、テーブル間の参照関係（例：注文は必ず存在する商品を参照する、など）をデータベース側で宣言的に表現する外部キー制約をサポートしていませんでした。

分散データベースで外部キーを実装するには、複数ノードをまたぐ整合性チェックとコンフリクト解決という技術的困難がありました。制約がなかった間は、開発者がアプリケーションコード側でこれらのチェックを実装する必要があり、実装漏れや競合状態による不整合リスクを常に抱えていました。

今回のサポートにより、参照整合性ルールをデータベース層に宣言することができ、アプリケーションの信頼性・保守性が大きく向上します。

新機能の概要

Aurora DSQL の新規・既存テーブルに FOREIGN KEY 制約を宣言できるようになりました。Aurora DSQL が利用可能なすべての AWS リージョンで利用可能です。

参照アクション

参照先の行が削除・更新されたときの動作を以下の 5 種類から選択できます。

アクション 動作
NO ACTION（デフォルト） 制約違反が残る場合はエラー。DEFERRABLE 指定時はコミット時まで遅延可能
RESTRICT 即座にエラー。遅延不可
CASCADE 参照元の行を自動的に削除または更新
SET NULL 参照元の外部キー列を NULL に設定
SET DEFAULT 参照元の外部キー列をデフォルト値に設定

マッチタイプ

マッチタイプ 動作
MATCH SIMPLE（デフォルト） 外部キー列の一部が NULL であれば参照チェックをスキップ
MATCH FULL 複合外部キーの場合、全列が NULL か全列が非 NULL でなければならない

遅延可能制約（Deferrability）

DEFERRABLE オプションにより、制約チェックのタイミングを制御できます。

オプション チェックタイミング
NOT DEFERRABLE（デフォルト） 各ステートメント実行直後
DEFERRABLE INITIALLY IMMEDIATE デフォルトは各ステートメント後。トランザクション内で SET CONSTRAINTS ... DEFERRED により遅延可能
DEFERRABLE INITIALLY DEFERRED デフォルトはコミット時。トランザクション内で SET CONSTRAINTS ... IMMEDIATE により即時化可能

整合性保証の仕組み

Aurora DSQL は 2 段階で参照整合性を維持します。

  1. スナップショット検証（トランザクション実行中）
    各トランザクションはその開始時点のスナップショットに対して参照整合性を検証します。ロックを取得せず読み取るため、他のトランザクションが並行して参照先・参照元テーブルを変更し続けることができます。

  2. コミット時の競合解決
    スナップショット検証後、別トランザクションがコミットの間に参照先行を削除したり、競合する参照元行を挿入したりした場合、Aurora DSQL はシリアライゼーションエラーでトランザクションを失敗させます。これにより「参照先が存在しない参照元」が確定することはありません。

使い方

1. 列制約として定義する（単一列の外部キー）

最もシンプルな形式です。列定義の後ろに REFERENCES を記述します。

-- products テーブル（参照先）
CREATE TABLE products (
    product_no integer PRIMARY KEY,
    name       text,
    price      numeric
);

-- orders テーブル（参照元）：product_no は products に存在する値のみ許可
CREATE TABLE orders (
    order_id   integer PRIMARY KEY,
    product_no integer REFERENCES products,   -- 主キーを自動参照
    quantity   integer
);

2. テーブル制約として定義する（複合外部キー）

複数列をまとめて外部キーにする場合は FOREIGN KEY (...) 構文を使います。

CREATE TABLE inventory (
    warehouse_id integer,
    product_no   integer,
    quantity     integer,
    PRIMARY KEY (warehouse_id, product_no)
);

CREATE TABLE shipments (
    shipment_id  integer PRIMARY KEY,
    warehouse_id integer,
    product_no   integer,
    FOREIGN KEY (warehouse_id, product_no)
        REFERENCES inventory (warehouse_id, product_no)
);

3. 参照アクションを指定する

削除時に参照元を連鎖削除する例（ON DELETE CASCADE）。

CREATE TABLE orders (
    order_id   integer PRIMARY KEY,
    product_no integer REFERENCES products ON DELETE CASCADE,
    quantity   integer
);

削除を即座に拒否する例（ON DELETE RESTRICT）。

CREATE TABLE orders (
    order_id   integer PRIMARY KEY,
    product_no integer REFERENCES products ON DELETE RESTRICT,
    quantity   integer
);

4. 遅延可能制約を定義する

同一トランザクション内で参照先・参照元を任意の順序で挿入したい場合に有効です。

CREATE TABLE orders (
    order_id   integer PRIMARY KEY,
    product_no integer REFERENCES products DEFERRABLE INITIALLY DEFERRED,
    quantity   integer
);
-- コミット時まで外部キーチェックが行われないため、
-- product 行より先に order 行を挿入しても問題なし

5. 自己参照外部キー（ツリー構造）

同一テーブルへの参照も可能です。

CREATE TABLE tree (
    node_id   integer PRIMARY KEY,
    parent_id integer REFERENCES tree,  -- 自己参照
    name      text
);

6. 既存テーブルへの制約追加

既存テーブルには ALTER TABLE で外部キーを追加できます。

ALTER TABLE orders
    ADD CONSTRAINT fk_product
    FOREIGN KEY (product_no) REFERENCES products (product_no);

注意点

⚠️ 追加の読み取りコストが発生する

参照元・参照先テーブルへのすべての DML（INSERT / UPDATE / DELETE）に、参照整合性チェックのための追加読み取りが発生します。外部キー制約を追加する前に、実際のワークロードでベンチマークを実施し、パフォーマンス要件を満たすことを確認してください。

⚠️ CASCADE / SET NULL / SET DEFAULT はトランザクション行変更数制限に注意

CASCADE・SET NULL・SET DEFAULT アクションは参照元テーブルの行を自動的に変更するため、その変更数も Aurora DSQL のトランザクション行変更数制限にカウントされます。参照元の行数が多い、あるいは予測困難な場合は NO ACTION または RESTRICT の使用を推奨します。

⚠️ 競合はロック待機ではなくシリアライゼーションエラー

Aurora DSQL の外部キーはロック方式ではなく楽観的並行制御を使用しています。競合が発生した場合、ロック待機は発生せず、即座にシリアライゼーションエラー（エラーコード OC000、SQLSTATE 40001）が返されます。

ERROR: change conflicts with another transaction (OC000) (SQLSTATE 40001)

アプリケーションにはトランザクションのリトライロジックを必ず実装してください。

⚠️ 頻繁に更新されるキー列への参照は競合を増やす

多数の参照元行が同一の参照先行を参照しており、かつその参照先のキー列が頻繁に変更される場合、コミット時競合が多発します。頻繁に変更される値は非キー列に移動することを検討し、参照される列（キー列）を安定させるよう設計してください。非キー列の変更は外部キーの競合を引き起こしません。

ℹ️ DEFERRABLE は外部キー制約のみ対応

Aurora DSQL において DEFERRABLE オプションが有効なのは外部キー制約に限られます。他の制約（UNIQUE、CHECK など）では使用できません。
