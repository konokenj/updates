Amazon BedrockがIAMユーザー・ロール別コスト配分をサポート、CUR 2.0とCost Explorerで推論コストの帰属が可能に

FEAT AWS What's New · 2026/4/9
要約: Amazon BedrockのモデルI推論コストを、呼び出し元のIAMプリンシパル（ユーザー・ロール）単位でCUR 2.0およびCost Explorerに自動記録。チーム・プロジェクト・コストセンター別のタグを活用し、CloudTrailとの手動突き合わせなしにBedrockコストのチャージバック・ショーバックを実現。

新機能の背景

生成AIの業務活用が加速する中で、「誰が Amazon Bedrock のモデル推論コストをどれだけ使っているか」 を把握することは、組織にとってますます重要な課題になっています。

しかし従来は、Bedrock の推論コストをモデル単位・リージョン単位で確認することはできても、呼び出し元（IAMユーザーやIAMロール）との紐付けは AWS の請求データに含まれていませんでした。そのため、チーム・プロジェクト・アプリケーション別にコストを帰属（チャージバック・ショーバック）させるには、以下のような煩雑な手作業が必要でした。

  • AWS CloudTrail で Bedrock API の呼び出し履歴を収集
  • Amazon CloudWatch ログと突き合わせて呼び出し元を特定
  • 請求データと手動でマージしてコストを計算

このプロセスは運用負荷が高く、リアルタイム性にも欠けていました。今回のリリースにより、既存の AWS コスト管理ツール（Cost Explorer・CUR 2.0）だけで、IAMプリンシパル単位の Bedrock コスト分析が完結するようになりました。

新機能の概要

Amazon Bedrock が AWS Cost and Usage Report 2.0（CUR 2.0） および AWS Cost Explorer において、IAMプリンシパル（IAMユーザー・IAMロール）単位のコスト配分をサポートしました。（2026年4月9日リリース、全 AWS 商用リージョンで利用可能）

追加された主な機能

機能 内容
CUR 2.0 新列 line_item_iam_principal Bedrock API を呼び出した IAM プリンシパルの ARN が行ごとに自動記録される
IAMプリンシパルタグのコスト配分 IAM ユーザー・ロールに付けたタグ（team・project・cost-center 等）を Cost Explorer や CUR 2.0 でコスト分析軸として利用できる
Cost Explorer でのグループ化・フィルタリング IAMプリンシパルタグ値ごとにコストを集計・絞り込みできる

line_item_iam_principal 列の値の形式

CUR 2.0 に追加される新列には、以下のような IAM ARN が格納されます。

ARN の例 呼び出し元の種別
arn:aws:iam::123456789012:user/alice IAM ユーザー
arn:aws:iam::123456789012:role/app-role IAM ロール
arn:aws:sts::123456789012:assumed-role/app-role/session-name AssumeRole セッション

CUR 2.0 のタグ列プレフィックス

IAMプリンシパルタグは、他のタグ種別（リソースタグ・アカウントタグ等）と区別するために iamPrincipal/ というプレフィックスが自動付与されます。

iamPrincipal/department  → 部門タグ
iamPrincipal/cost-center → コストセンタータグ
iamPrincipal/team        → チームタグ
iamPrincipal/project     → プロジェクトタグ

仕組み

CUR 2.0 でIAMプリンシパルデータを有効化すると、AWS は Bedrock API が呼び出されるたびに、その呼び出し元の IAM プリンシパル ARN を line_item_iam_principal 列に自動記録します。

さらに IAM プリンシパルにタグが設定されていれば、そのタグも CUR 2.0 のタグ列に自動的に取り込まれます。これにより、CloudTrail や CloudWatch との手動突き合わせなしに、組織の階層構造（チーム・プロジェクト・コストセンター）に沿ったコスト可視化が実現します。

Bedrock API 呼び出し
    └─ 呼び出し元 IAM ARN → line_item_iam_principal 列に記録
    └─ IAM プリンシパルのタグ → iamPrincipal/<タグキー> 列に記録
           ↓
    CUR 2.0 / Cost Explorer で集計・分析

利用開始手順

ステップ 1：IAMコンソールでプリンシパルにタグを付与する

  1. IAM コンソール を開く
  2. Bedrock API を呼び出す IAM ユーザーまたはロールを選択する
  3. 組織構造を表すタグを付与する
推奨タグキーの例：
  department  （部門）
  cost-center （コストセンター）
  team        （チーム）
  project     （プロジェクト）
  environment （環境：prod / dev / staging）

注意： Bedrock では、タグが付いた IAM プリンシパルが 少なくとも 1 回 Bedrock API を呼び出した後 でないと、コスト配分タグページにそのタグが表示されません。

ステップ 2：コスト配分タグとして有効化する

  1. Billing and Cost Management コンソール を開く
  2. 左ナビゲーションペインの 「コスト組織」→「コスト配分タグ」 を選択する
  3. フィルターで 「IAM プリンシパル」 タイプを選択する
  4. 有効化したいタグキーを選択し、「有効化」 をクリックする
  5. ステータスが 「アクティブ」 になるまで待つ（最大 24 時間）

注意： タグ付与後にコスト配分タグページへ表示されるまで最大 24 時間、その後アクティブになるまでさらに最大 24 時間かかります（合計最大 48 時間）。

ステップ 3：CUR 2.0 でIAMプリンシパルデータを有効化する

  1. Billing and Cost Management コンソールの 「データエクスポート」 を開く
  2. 「新しいエクスポートを作成」 で 「Standard data export（CUR 2.0）」 を選択する
  3. 「追加のエクスポートコンテンツ」 の中から 「呼び出し元 ID（IAMプリンシパル）の配分データを含める」 を選択する
  4. 設定を保存する

これにより line_item_iam_principal 列と IAMプリンシパルタグ列が CUR 2.0 エクスポートに追加されます。

ステップ 4：Cost Explorer / CUR 2.0 でコストを分析する

Cost Explorer でタグ別に集計する場合：

  1. Cost Explorer を開く
  2. 「グループ化」 ドロップダウンから 「タグ」 を選択する
  3. 有効化した IAMプリンシパルタグ（例：iamPrincipal/department）を選択する
  4. タグ値ごとに集計されたコストを確認する

Cost Explorer でタグ別にフィルタリングする場合：

  1. Cost Explorer の 「フィルタ」 セクションで 「タグ」 を選択する
  2. 有効化した IAMプリンシパルタグと値を指定して絞り込む

CUR 2.0 で分析する場合：

  • line_item_iam_principal 列：Bedrock API を呼び出した IAM ARN を確認
  • resource_tags_iamPrincipal_department 等：IAMプリンシパルタグ別のコストを確認

注意事項

⏱ タグ反映には最大 48 時間かかる

IAM プリンシパルへのタグ付与 → コスト配分タグページへの表示まで 最大 24 時間、さらにアクティブ化まで 最大 24 時間 かかります。設定直後に Cost Explorer や CUR 2.0 に反映されない場合は仕様通りです。

🔑 タグ表示の前提：1回以上の Bedrock API 呼び出しが必要

Amazon Bedrock 特有の挙動として、IAM プリンシパルが少なくとも 1 回 Bedrock API を呼び出した後 でないと、コスト配分タグとして有効化できる状態になりません。IAM ユーザー・ロール・AssumeRole セッションすべてに適用されます。

📦 CUR ファイルサイズの増大に注意

IAMプリンシパルデータを有効化すると、CUR 2.0 の行数が 呼び出し元 IAMプリンシパルの種類数に比例して増加 します。出力先 S3 バケットのストレージコストと、Athena・QuickSight 等でのデータ処理コストへの影響を事前に試算することを推奨します。

🏷 高カーディナリティタグは避ける

タグ値の種類が多すぎるタグキー（ユニークなセッション ID・タイムスタンプ・ランダムな GUID など）はコスト分析の粒度が過剰になるため推奨されません。組織構造を反映した意味のある、低カーディナリティのタグ設計を心がけてください。

推奨するタグ設計 避けるべきタグ設計
team: data-science（チーム名） session-id: abc123xyz...（一意のID）
cost-center: cc-1234（コストセンターコード） timestamp: 2026-04-09T12:00:00Z（タイムスタンプ）
environment: production（環境名） request-id: f8a2b...（リクエストID）

🔄 CUR 2.0（Standard data export）が前提条件

この機能は CUR 2.0 でのみ利用できます。旧来の CUR（Legacy CUR）には対応していません。まだ移行していない場合は、Billing and Cost Management コンソールから CUR 2.0 に移行が必要です。

📊 既存の Bedrock リソースタグとの使い分け

従来のリソースタグは「モデル・エンドポイント単位（何を使ったか）」の分析に向いています。IAMプリンシパルタグは「呼び出し元単位（誰が使ったか）」の分析に特化しています。両者を組み合わせることで、「どのチームが・どのモデルを・いくら使ったか」という多軸のコスト分析が可能になります。
