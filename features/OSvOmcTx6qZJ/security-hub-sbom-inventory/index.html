AWS Security Hub がSBOMインベントリを提供開始 — EC2・ECR・Lambdaのソフトウェア構成を組織全体で一元管理

FEAT AWS What's New · 2026/11/6
要約: Amazon InspectorのSBOMスキャン結果をSecurity Hubが自動集約し、EC2・ECRコンテナイメージ・Lambda関数のインストール済みパッケージを組織横断で継続的に可視化。追加設定不要でSecurity Hub Essentialsプランに含まれ、CVE影響範囲の即時特定やコンプライアンス証跡の作成に活用できる。

新機能の背景

近年、ソフトウェアサプライチェーン攻撃（SolarWinds、Log4Shell など）が相次いで発生したことで、「自社のシステムにどのソフトウェアが入っているか」を正確に把握するニーズが急増しました。これに応える形で SBOM（Software Bill of Materials：ソフトウェア部品表） が注目を集めており、米国政府の大統領令 14028 をはじめ、金融・医療・製造など多くの業界規制がその作成・管理を求め始めています。

しかし、大規模なクラウド環境では EC2 インスタンス・コンテナイメージ・Lambda 関数が常に増減しており、SBOM を手動でエクスポート・突き合わせるだけでも膨大な運用コストがかかります。また、新たな脆弱性（CVE）が公開された際に「どのリソースが影響を受けるか」を迅速に特定できなければ、インシデント対応が後手に回ります。

これまで Amazon Inspector は各リソースの SBOM を生成していましたが、それはリソース単位の情報にとどまり、組織全体を横断した一元的なビューは提供されていませんでした。AWS Security Hub が SBOM インベントリ機能を追加したことで、この課題が解消されます。

新機能の概要

AWS Security Hub の SBOM インベントリは、Amazon Inspector がコンピューティングリソースをスキャンするたびに生成する SBOM を自動収集し、組織全体の最新ソフトウェア台帳として一元管理する機能です。

SBOM ページの主な情報

  • パッケージテーブル — パッケージ名・バージョン・パッケージ種別（rpm、npm、pip など）・インストール済みリソース数を一覧表示。同一パッケージは何台にインストールされていても 1 行 にまとめて表示され、「Resources」列の件数で展開範囲を把握できます。
  • サマリーチャート — "Packages by type"（種別ごとのインストール数分布）と "Most common packages"（最も広く使われているパッケージ Top N）の 2 種類のグラフ。チャートの値をクリックするとテーブルが絞り込まれます。
  • フィルター・グループ化 — パッケージ名・バージョン・パッケージ種別・アカウント・リージョン・リソース種別・クラウドプロバイダーで絞り込み可能。よく使うフィルターセットを保存して再利用できます。
  • リソース詳細の「Installed software」タブ — 特定リソースに移動すると、そのリソースにインストールされているすべてのパッケージを確認でき、ファインディングのトリアージ時にリソースの役割・重要度判断に活用できます。
  • Security Hub API — コンソール操作だけでなく API 経由でもインベントリをクエリできます。

料金・提供リージョン

  • Security Hub Essentials プランに追加費用なしで含まれています。 Inspector と Security Hub CSPM の費用が Essentials プランとして統合されたリソースベースの料金体系に一本化されており、SBOM インベントリはその中に組み込まれています。
  • Security Hub が利用可能なすべての AWS リージョンで利用できます。

使い方

前提条件の確認

  1. 対象アカウント・リージョンで AWS Security Hub が有効になっていること。
  2. インベントリに含めたいリソース種別（EC2・ECR・Lambda）に対して Amazon Inspector が有効になっていること（Inspector が有効でないリソース種別はインベントリに表示されません）。

Inspector を有効化していない場合、SBOM ページには「Amazon Inspector is not enabled」メッセージと「Enable Inspector」ボタンが表示されます。このボタンから Security Hub の設定画面に遷移して Inspector を有効化できます。

SBOM ページへのアクセス手順

  1. Security Hub コンソール を開く。
  2. 左ナビゲーションの Inventory → SBOM を選択。

他の AWS サービスとの連携可能性

  • Amazon Inspector — SBOM の生成元。Inspector のスキャン対象を広げるほどインベントリが充実します。
  • AWS Organizations — 管理者アカウントで組織全体のインベントリを一元表示できます。
  • Security Hub API / Amazon EventBridge — インベントリ変更イベントを下流の SIEM（Amazon Security Lake, Splunk など）や SOAR ツールに連携し、自動修復ワークフローを構築できます。
  • AI Inventory 機能（2026年7月リリース）— Inspector の SBOM 解析を活用して EC2・ECR 上の AI モデルや推論エンドポイントも自動検出します。SBOM インベントリと相補的に利用できます。

注意点

  1. Inspector の有効化範囲に依存する — SBOM インベントリは「Amazon Inspector がスキャンしているリソース種別」のみを反映します。例えば Inspector で EC2 のみ有効にしている場合、Lambda や ECR はインベントリに表示されません。組織全体の可視性を確保するには、対象リソース種別すべてで Inspector を有効にする必要があります。

  2. 反映まで数時間かかる場合がある — Inspector が新しい SBOM を生成した後、Security Hub の SBOM ページに反映されるまで 数時間かかることがあります。リアルタイム性が求められる用途では、Inspector の直接出力も合わせて参照してください。

  3. リソース削除時の自動クリーンアップ — インスタンスが終了・削除されたり Inspector のカバレッジ外になったりすると、そのリソースのソフトウェアはインベントリから自動的に削除されます。定期的なスナップショット保持が必要な場合は API で定期エクスポートする運用が必要です。

  4. アカウントの表示権限に注意 — メンバーアカウントでは自アカウントのリソースしか参照できません。組織全体を俯瞰したい場合は、Organizations の管理者（委任管理者）アカウントから Security Hub を操作してください。

  5. Azure リソースは追加設定が必要 — Azure 仮想マシンや Azure Container Registry のリソースをインベントリに含めるには、Security Hub と Microsoft Azure を接続する追加設定が必要です。設定なしでは AWS リソースのみが対象です。

  6. Security Hub Essentials プランの対象外サービスは別途課金 — Lambda コードスキャン（高度なコード解析）は Essentials に含まれず「Additional capabilities」として別途課金されます。通常の Lambda 関数スキャン（パッケージ一覧取得）は Essentials 内で提供されます。
