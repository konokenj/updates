Amazon CloudWatch Logsがマネージドsyslogインジェスチョンをサポート、エージェント不要でネットワーク機器のログを直接収集

FEAT AWS What's New · 2026/6/23
要約: ファイアウォール、ルーター、スイッチ、LinuxサーバーからのsyslogをエージェントなしでCloudWatch Logsに直接取り込み可能に。TCP/TCP+TLS/UDP対応のVPCエンドポイント経由で送信し、RFC 5424・RFC 3164・Cisco FTD/ASA形式を自動解析。Logs Insightsで構造化フィールドを使ったクエリも可能。

新機能の背景

ファイアウォール、ルーター、スイッチ、Linux サーバーなどのネットワーク機器・サーバーは、運用ログとして syslog メッセージを継続的に生成しています。これまで、これらのログを Amazon CloudWatch Logs に取り込むには、各ホストに ログ収集エージェント（CloudWatch Agent など）をインストール・管理する必要がありました。

しかし、ネットワーク機器（ルーターやスイッチなど）はそもそもエージェントのインストール自体をサポートしていないケースが大半であり、分散した環境全体でエージェントを展開・維持することは大きな運用オーバーヘッドになっていました。

このような課題を解消するため、エージェント不要でネットワーク機器を含む多様なインフラから直接 syslog を CloudWatch Logs に送信できるマネージドな仕組みとして、本機能が提供されました。インフラログの可視化を一元化し、ログ収集パイプラインの構築・保守コストを大幅に削減することを目的としています。

新機能の概要

Amazon CloudWatch Logs のマネージド syslog インジェスチョンは、ファイアウォール、ルーター、スイッチ、Linux サーバーなどから syslog メッセージをエージェントなしで直接 CloudWatch Logs に取り込める新機能です。

アーキテクチャ概要

syslog ソース（ネットワーク機器・サーバー）は、自アカウント内の VPC エンドポイントに対して syslog メッセージを送信します。トラフィックは AWS PrivateLink 経由でトンネリングされ、CloudWatch Logs の syslog サービスがメッセージを解析してロググループに書き込みます。

送信元の場所 接続方法
VPC 内のリソース VPC エンドポイントに直接送信
オンプレミス・ブランチオフィス・コロケーション施設 VPN または AWS Direct Connect 経由で VPC エンドポイントに接続

対応プロトコルとポート

プロトコル ポート 備考
TCP + TLS 6514 転送中に暗号化。コンプライアンス要件に推奨。TLS 証明書は AWS マネージド（Amazon Trust Services 発行）で、クライアント側の特別な設定不要

対応 syslog フォーマット

CloudWatch Logs は以下の 3 つのフォーマットを自動検出・解析します。

  • RFC 5424（新形式）：構造化データ、ISO 8601 タイムスタンプ、アプリケーション名・プロセス ID を含む
  • RFC 3164（BSD syslog、旧来形式）：ファイアウォール・ルーター・スイッチで広く使用されるレガシー形式
  • Cisco FTD/ASA：Cisco Firepower Threat Defense および Adaptive Security Appliance 専用形式（%FTD- または %ASA- タグで識別）

自動抽出フィールド

メッセージはロググループに生の形式で保存されると同時に、構造化フィールドが自動的に抽出され、CloudWatch Logs Insights でのクエリが可能です。

RFC 5424 / RFC 3164 共通の主要フィールド：

フィールド 内容
facility / facilityCode ログカテゴリ名 / 数値コード（0〜23）
severity / severityCode 重要度名 / 数値コード（0〜7）
hostname 送信元デバイスのホスト名
appName アプリケーション名
timestamp タイムスタンプ（ISO 8601 形式に変換）
message メッセージ本文

RFC 5424 追加フィールド： procId、msgId、structuredData（構造化データ要素）

Cisco FTD/ASA 固有フィールド： device（FTD/ASA/FMC-AUDIT-LOG）、deviceId、messageId（例：106023）、subsystem

利用開始方法

  1. アカウント内に CloudWatch Logs syslog サービス用の VPC エンドポイントを作成する
  2. ネットワーク機器・サーバーの syslog 送信先を VPC エンドポイントのアドレスと対応ポートに設定する
  3. メッセージが自動解析され、指定したロググループに書き込まれる
  4. CloudWatch Logs Insights で severity やホスト名などの構造化フィールドを使ってクエリ・分析する

利用可能リージョン

すべての商用 AWS リージョンで利用可能（ただし以下 3 リージョンを除く）：中東（UAE）、中東（バーレーン）、イスラエル（テルアビブ）

注意点

⚠️ メッセージのロスとリカバリー不可

syslog プロトコルにはサーバーからのアプリケーション層の ACK（応答確認）が存在しません。以下の状況でメッセージがドロップされ、リカバリーは不可能です。

  • 対象ロググループが削除されている
  • リソースポリシーが正しく設定されていない
  • アカウントの PutLogEvents クォータを超過している

ドロップを検知するには、CloudWatch の SyslogMessagesDropped メトリクスを監視してください。Reason ディメンションでドロップ理由を確認し、適切な対処（ロググループ再作成、ポリシー修正、クォータ引き上げ申請）が可能です。

⚠️ UDP はベストエフォート

UDP はネットワーク状況によりメッセージが失われる可能性があります。確実な配信が必要な場合は TCP または TCP + TLS を使用してください。

⚠️ クォータと制限

制限項目 値 備考
最大メッセージサイズ（TCP） 64 KB 標準的な syslog は通常この上限を下回る
最大メッセージサイズ（UDP） 8 KB 標準的な syslog は通常この上限を下回る
インジェスチョンスループット PutLogEvents クォータと共有 デフォルト：アカウント・リージョンあたり 5,000 リクエスト/秒（Service Quotas から引き上げ申請可能）

⚠️ 利用不可リージョン

現時点では 中東（UAE）、中東（バーレーン）、イスラエル（テルアビブ） では利用できません。これらのリージョンを使用している場合は、代替のログ収集方法（CloudWatch Agent など）が引き続き必要です。
