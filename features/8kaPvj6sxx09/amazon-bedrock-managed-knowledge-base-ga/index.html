Amazon Bedrock Managed Knowledge Baseが一般提供開始——フルマネージドRAGサービス

FEAT AWS What's New · 2026/6/17
要約: ベクトルDB・データパイプライン・検索インフラ不要のフルマネージドRAGサービスが正式GA。S3・SharePoint・Confluenceなど6種コネクタ、マルチホップ対応のAgentic Retrieval、ハイブリッド検索を内蔵。Bedrock AgentCoreとネイティブ統合し、東京リージョンでも利用可能。

新機能の背景

RAG（Retrieval-Augmented Generation）は、企業独自のデータをファンデーションモデルに組み合わせ、回答の精度・関連性を高める手法として広く注目されています。しかし従来の RAG 実装には、ベクトルデータベースの構築・運用、データパイプラインの整備、埋め込みモデルや再ランキングモデルの選定・管理、検索インフラのスケーリングなど、多くの技術的負担が伴っていました。

Amazon Bedrock Knowledge Bases にはこれまで「カスタムナレッジベース」（Amazon OpenSearch Serverless や Aurora、Pinecone などの自前ベクトルストアを使用する方式）が存在していましたが、インフラ管理を AWS に完全に委ねられる選択肢はありませんでした。

この課題を解決するため、ベクトルストア・データ取り込みパイプライン・検索最適化のすべてをフルマネージドで提供する Managed Knowledge Base が一般提供（GA）となりました。開発チームがインフラ運用ではなくアプリケーション開発そのものに集中できる環境を整えることが、本リリースの背景にあります。

新機能の概要

Amazon Bedrock Managed Knowledge Base は、RAG に必要なすべてのインフラ（ベクトルストア・埋め込み・再ランキング・取り込みパイプライン）を AWS が完全に管理するフルマネージド RAG サービスです。ナレッジベースタイプとして MANAGED を指定するだけで利用でき、ストレージは自動管理されます（必要に応じて KMS キーによる暗号化も可能）。

使い方

クイックスタート（コンソール）

  1. Amazon Bedrock コンソール を開く
  2. Knowledge Bases → Create knowledge base を選択
  3. ナレッジベースタイプとして Managed を選択
  4. データソースコネクタ（S3 / SharePoint / Confluence など）を接続
  5. データソースを同期（以降は自動同期）
  6. API または Amazon Bedrock Agents から検索・回答生成を呼び出す

API 呼び出し例（通常検索 / 回答生成）

import boto3

bedrock_agent_runtime = boto3.client("bedrock-agent-runtime", region_name="us-east-1")

# 検索のみ（Retrieve）
response = bedrock_agent_runtime.retrieve(
    knowledgeBaseId="YOUR_KB_ID",
    retrievalQuery={"text": "休暇申請の手続きを教えてください"}
)

# 検索 + 回答生成（RetrieveAndGenerate）
response = bedrock_agent_runtime.retrieve_and_generate(
    input={"text": "休暇申請の手続きを教えてください"},
    retrieveAndGenerateConfiguration={
        "type": "KNOWLEDGE_BASE",
        "knowledgeBaseConfiguration": {
            "knowledgeBaseId": "YOUR_KB_ID",
            "modelArn": "arn:aws:bedrock:us-east-1::foundation-model/anthropic.claude-3-sonnet-20240229-v1:0"
        }
    }
)
print(response["output"]["text"])

注意点

Managed vs Custom ナレッジベースの選択

Amazon Bedrock Knowledge Bases には Managed（本 GA）と Custom（自前ベクトルストア管理）の 2 種類があります。インフラ管理を最小化してすぐに始めたい場合は Managed を、OpenSearch Serverless や Aurora などを独自設定でチューニングしたい高度なユースケースでは Custom を選択してください。

利用可能リージョンの制限

2026年6月時点では、対応リージョンは US East（N. Virginia）・US West（Oregon）・アジアパシフィック（シドニー・東京）・ヨーロッパ（ダブリン・フランクフルト・ロンドン）・AWS GovCloud（US-West）の合計 8 リージョンです。日本からは**東京リージョン（ap-northeast-1）**が対象に含まれています。対応リージョンは今後拡大が見込まれますが、本番利用前に最新状況を公式ドキュメントで確認してください。

Agentic Retrieval の料金モデル

Agentic Retrieval はトークン課金ではなくクエリ単位のフラット料金モデルです。複雑なマルチホップクエリで複数の推論ステップが発生しても、料金が急増しません。ただし、独自モデル（BYOM）を持ち込む場合はコストが桁違いに高くなる可能性があるため、デフォルトの AWS 独自検索モデルとの比較を事前に行うことを推奨します。

カスタム埋め込み・再ランキングモデルの利用

デフォルトでは AWS がサービス管理モデルを使用しますが、独自の Bedrock 埋め込みモデルや再ランキングモデルを持ち込むことも可能です。既存の検索スタックとの統合を検討している場合に有効です。

データ同期のタイミング

データソースへの変更は自動同期されますが、同期頻度やタイミングはデータソースの種類によって異なります。リアルタイム性が求められるユースケースでは、同期スケジュールと許容レイテンシを事前に確認してください。

セキュリティ・暗号化

保存データの暗号化には KMS キーを任意で指定できます。AgentCore 統合では自動生成パーミッションと組み込みオブザーバビリティが提供されますが、本番環境では IAM ポリシーの最小権限原則に沿った設定を改めて確認することを推奨します。
