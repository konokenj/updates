Amazon Textractのテキスト検出モデルが刷新 — 40言語以上に対応・精度向上・多言語テーブル抽出を強化

FEAT AWS What's New · 2026/11/2
要約: Amazon TextractのDetectDocumentText・AnalyzeDocument APIに新テキスト検出モデルが自動適用。対応言語を40以上に拡大（アラビア語・日中韓・キリル文字など）、長い単語や手書き文字の認識精度も向上。結合セル・傾きを含む複雑なテーブル抽出も強化。APIの変更・追加料金は一切不要。

新機能の背景

Amazon Textract は OCR（光学文字認識）を超えた機械学習ベースの文書解析サービスとして、金融・医療・行政など多様な業界で活用されてきました。しかし、グローバルビジネスの拡大に伴い、多言語文書を高精度で処理したいというニーズが急速に高まっています。

従来のモデルでは、対応言語が限られていたため、アラビア語・キリル文字・東アジア言語などを含む文書の処理精度に課題がありました。また、傾きや歪みのあるテーブル、結合セルを含む複雑な帳票、長い単語や手書き文字の認識精度についても改善の余地がありました。請求書・フォーム・身分証明書などビジネスクリティカルな文書を大規模・多言語で自動処理したいユースケースでは、これらの制限がシステム導入の障壁になることがありました。

こうした背景を受け、Amazon Textract はテキスト検出モデルそのものを刷新し、精度・言語カバレッジ・テーブル抽出の堅牢性を一度に底上げするアップデートを実施しました。

Amazon Textract のテキスト検出モデルが更新され、以下の 3 つの領域で大きな改善が加えられました。

2. テキスト認識精度の向上

  • 長い単語の認識精度向上: メールアドレスや専門用語など文字数の多い単語をより正確に抽出できるようになりました。
  • 手書き文字検出の強化: 手書き文字の認識精度が改善され、手書きを含む帳票処理の自動化が進めやすくなりました。

3. 多言語テーブル抽出の堅牢化

以下のような難易度の高いテーブルレイアウトへの対応が強化されました。

  • 結合セル（Merged Cells）: セル結合を含む複雑なテーブル構造を正確に解釈
  • 傾き・回転テーブル（Skewed / Rotated Tables）: スキャン品質が低い文書や斜めに撮影された文書にも対応
  • 欠損・破損テーブル（Partial / Corrupted Tables）: 一部が欠けたテーブルや破損した文書でも安定した抽出が可能

使い方

今回のアップデートは既存ユーザーには自動適用されるため、新たな設定作業は不要です。

既存ユーザー：ゼロ対応で即時恩恵

現在 DetectDocumentText または AnalyzeDocument API を呼び出しているアプリケーションは、コードを一切変更せず、そのままの API 呼び出しで新モデルによる改善済みの結果を受け取ることができます。

新規ユーザー：利用開始手順

  1. AWS アカウントを作成し、IAM ユーザーに AmazonTextractFullAccess ポリシーを付与します。
  2. 処理対象ドキュメント（JPEG / PNG / PDF / TIFF）を Amazon S3 にアップロードするか、バイト配列として直接渡します。
  3. 用途に応じて API を呼び出します。
import boto3

client = boto3.client('textract', region_name='us-east-1')

# 同期テキスト検出（最大 10 MB）
response = client.detect_document_text(
    Document={'S3Object': {'Bucket': 'my-bucket', 'Name': 'invoice.pdf'}}
)

# テーブル・フォームも含む文書解析
response = client.analyze_document(
    Document={'S3Object': {'Bucket': 'my-bucket', 'Name': 'form.pdf'}},
    FeatureTypes=['TABLES', 'FORMS']
)

大容量・大量処理の場合は非同期 API（StartDocumentTextDetection / StartDocumentAnalysis）を使用してください。

注意点

新モデルへの移行はシームレスですが、以下の点を事前に把握しておくことを推奨します。

  • モデルのオプトアウト不可: 更新は自動適用であり、旧モデルに戻す手段は提供されていません。本番環境への影響が懸念される場合は、事前にステージング環境で主要な文書タイプの出力を確認しておくことを推奨します。精度向上による結果の変化が、下流の処理ロジック（信頼スコアの閾値や特定フィールドの正規表現マッチングなど）に影響しないか検証してください。

  • フォーム抽出（キーバリューペア）の言語制限は継続: AnalyzeDocument の FORMS 機能（キーバリューペア・チェックボックス抽出）は引き続き 英語・スペイン語・イタリア語・ポルトガル語・フランス語・ドイツ語 の 6 言語のみ対応です。今回の多言語対応は主にテキスト検出（OCR）レイヤーの改善であり、フォーム解析機能の多言語化ではありません。

  • 手書き認識の多言語対応範囲: 手書き文字の認識精度向上はアナウンスされていますが、すべての新対応言語で均一に適用されるわけではありません。非ラテン文字の手書き認識については公式ドキュメントや実測での確認を推奨します。

  • 同期 API のファイルサイズ制限: DetectDocumentText および AnalyzeDocument（同期）は最大 10 MB のドキュメントサイズ制限があります。それを超える場合は StartDocumentTextDetection / StartDocumentAnalysis（非同期）を使用してください。

  • 対応ファイル形式: JPEG、PNG、PDF、TIFF のみ対応です。その他の形式（Word、Excel など）は事前に変換が必要です。
