AWS Security Agent、AIエージェントによる脅威モデリングをパブリックプレビューで提供開始

FEAT AWS What's New · 2026/6/17
要約: AWS Security Agent（AWS Continuum）がAIによる脅威モデリングをパブリックプレビューで追加。設計ドキュメントまたはソースコードを解析し、STRIDEフレームワークに基づく脅威の特定と緩和策を自動生成。Kiro・Claude Code（近日公開）・MCP経由でのIDE統合も対応。プレビュー期間中は追加料金なし。

新機能の背景

脅威モデリングは、アプリケーションがどのように攻撃される可能性があるかを体系的に洗い出すセキュリティプラクティスです。しかし従来は、STRIDE などのフレームワークに精通した専門家と、アーキテクチャ・データフロー・トラストバウンダリーを手動で読み解く多大な工数が必要でした。その結果、脅威モデリングは「やりたくてもできない」タスクとなり、設計段階でのリスク検出が後回しになりがちでした。

AWS Security Agent はもともと、設計レビュー・コードレビュー・ペネトレーションテストを一気通貫で自動化する「フロンティアエージェント」として、2025年 re:Invent でプレビュー公開されました。その後、オンデマンドペネトレーションテストの GA、全リポジトリコードレビューのプレビューと段階的に機能を拡張してきました。今回の脅威モデリング対応は、開発ライフサイクルの最上流（設計フェーズ）にセキュリティ専門知識を自動的に組み込むという同サービスのビジョンをさらに推し進める重要なマイルストーンです。

新機能の概要

AWS Security Agent（AWS Continuum の一部）に、AIエージェントによる脅威モデリング機能がパブリックプレビューとして追加されました（2026年6月17日より提供開始）。

入力ソース

設計ドキュメント（スコープドキュメント）、ソースコードリポジトリ（GitHub・GitLab・Bitbucket など）、またはその両方を入力として与えることができます。エージェントはこれらを深く解析し、アプリケーションの全体像を自律的に把握します。

自動生成されるアウトプット

アウトプット 内容
システム概要 アーキテクチャ構成・コンポーネント・トラストバウンダリー・データフロー・セキュリティポスチャの説明
脅威一覧 STRIDE カテゴリ別に分類された脅威（深刻度レベル付き）
緩和策 各脅威に対する具体的かつ実行可能な推奨対策

STRIDE フレームワークとは

STRIDE は Microsoft が提唱した脅威分類モデルで、以下の 6 カテゴリから成ります。

  • Spoofing（なりすまし）
  • Tampering（改ざん）
  • Repudiation（否認）
  • Information Disclosure（情報漏洩）
  • Denial of Service（サービス拒否）
  • Elevation of Privilege（特権昇格）

IDE 統合

Kiro パワー（拡張機能）や近日公開予定の Claude Code プラグイン、さらにオープンな MCP インテグレーションを通じて、任意の AI 対応 IDE から直接脅威モデルを生成・確認できます。コンテキストスイッチなしにインラインで結果を確認できるため、開発者体験を損なわずにセキュリティを組み込めます。

既存機能との位置づけ

AWS Security Agent はセキュリティカバレッジを開発ライフサイクル全体に渡って提供します。

フェーズ 機能 ステータス
設計時 設計レビュー・脅威モデリング（今回） プレビュー
開発時 コードレビュー（PR スキャン含む） プレビュー
デプロイ時 ペネトレーションテスト GA

使い方

コンソールから使う（基本的な手順）

  1. Security Agent コンソール を開く
  2. 「Enable threat model」 を選択する
  3. ソースコードリポジトリを接続する（GitHub・GitLab・Bitbucket 等）、または設計ドキュメントをアップロードする
  4. エージェントが自動的に解析を実行し、STRIDE 分類に基づく脅威モデルを生成する
  5. 生成されたシステム概要・脅威一覧・緩和策を確認し、設計の改善や実装計画に活用する

脅威モデルは再利用可能な設定として保存されます。コードや設計が変化するたびに再実行でき、反復的なセキュリティ評価を継続して行えます。

Kiro IDE から使う

Kiro パワー（aws-security-agent-kiro-power）をインストール後、以下のプロンプトを実行するだけで脅威モデルを生成できます。

Build a threat model for this application

生成された脅威モデルは .security-agent/threat_model.md としてローカルワークスペースに保存されます。初回セットアップ時は Set up AWS Security Agent と入力すると、エージェントスペースの確認・作成を対話的にガイドしてくれます。

MCP インテグレーション経由で使う

AWS Security Agent MCP サーバーを使えば、Claude Code（近日公開）や他の任意の MCP 対応 AI IDE・ツールから脅威モデリングを呼び出せます。

ユースケース別の活用シーン

  • 開発者: Kiro や Claude Code に組み込み、スペック（設計仕様）から脅威モデルを生成し、設計フェーズの段階で脅威を早期検出・対処する
  • セキュリティチーム: デプロイ前アセスメントとして、設計ドキュメントとソースコードに対して脅威モデルを実行し、リリース判断の根拠とする

注意点

  • パブリックプレビュー段階: 本機能は現在プレビューであり、本番クリティカルなワークロードへの適用には十分な検証が推奨されます。SLA や機能の安定性は GA 後に確定します。
  • プレビュー期間中は追加料金なし: 公開プレビュー期間中は脅威モデリング機能への追加コストは発生しません。ただし、プレビュー終了後の料金体系については AWS Security Agent 料金ページ を確認してください。また、2ヶ月間の無料トライアルも提供されています。
  • 利用可能リージョンの確認が必要: 脅威モデリングは AWS Security Agent がサポートするすべてのリージョンで利用可能ですが、サービス自体がまだすべての AWS リージョンで展開されているわけではありません。具体的な対応リージョンは AWS Capabilities by Region で確認してください。
  • Claude Code プラグインは近日公開予定: ブログ公開時点では Kiro パワーのみが利用可能で、Claude Code プラグインは「coming soon」となっています。
  • AIによる自動生成結果の確認: エージェントが生成した脅威モデルは自動化によるものであるため、アプリケーション固有のビジネスコンテキストや特殊な運用環境を反映しきれていない場合があります。セキュリティチームによるレビューと組み合わせてご利用ください。
