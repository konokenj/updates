Amazon SageMaker AIの推論エンドポイントがOpenAI互換APIをサポート

FEAT AWS What's New · 2026/5/21
要約: SageMaker リアルタイム推論エンドポイントがOpenAI互換APIパスを公開。OpenAI SDK・LangChain・Strands AgentsからエンドポイントURLを変更するだけで接続可能に。カスタム統合コードや既存コードの書き直しは不要。vLLM・SGLang DLCおよびカスタムコンテナに対応。

新機能の背景

AIアプリケーションの多くは、OpenAI SDK・LangChain・Strands Agents といったフレームワークを前提に構築されています。これらは OpenAI 互換の API 仕様を標準インターフェースとして採用しているため、従来 SageMaker のエンドポイントを利用するには、独自の API フォーマットへの対応・AWS SigV4 署名ラッパーの実装・既存コードの大幅な書き直しが避けられませんでした。

このような統合コストが、既存の OpenAI ベースのアプリケーションを SageMaker へ移行する際の大きな障壁となっていました。今回のアップデートはその障壁を取り除くことを目的としており、エンドポイント URL を変更するだけで、すでに動作している OpenAI 互換のコードをそのまま SageMaker エンドポイントに向けることができるようになります。

新機能の概要

Amazon SageMaker AI のリアルタイム推論エンドポイントが、OpenAI 互換の API パス（/openai/v1/chat/completions）を公開するようになりました。主な特徴は以下のとおりです。

エンドポイント URL の変更のみで移行完了

OpenAI SDK・LangChain・Strands Agents などのフレームワークに対して、追加のカスタムクライアント実装・コード書き直しが不要です。SDK 呼び出し・ストリーミングロジック・フレームワーク連携はすべてそのまま動作します。認証もエンドポイント URL の変更以外は変更不要です。

ベアラートークン認証

SageMaker Python SDK に含まれる generate_token 関数を使い、既存の AWS 認証情報から短命なベアラートークン（最大 12 時間有効）を生成します。追加の API キーや秘密情報の管理は不要です。トークン生成はローカルで完結するクライアントサイド処理（SigV4 プリサイン URL の Base64 エンコード）であり、ネットワーク呼び出しは発生しません。

単一モデルエンドポイントと推論コンポーネントの両方に対応

方式 概要 URL パターン
単一モデルエンドポイント 1 エンドポイント = 1 モデル .../endpoints/<NAME>/openai/v1
推論コンポーネント 1 エンドポイントに複数モデルをホスト、モデルごとに独立したリソース割り当て .../endpoints/<NAME>/inference-components/<IC_NAME>/openai/v1

使い方

ステップ 1: 必要なパッケージのインストール

pip install sagemaker openai

ステップ 2: IAM パーミッションの設定

エンドポイントを呼び出す IAM ロール／ユーザーに以下のポリシーをアタッチします。sagemaker:InvokeEndpoint は特定のエンドポイント ARN に絞り込むことが推奨されます。

{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": "sagemaker:InvokeEndpoint",
            "Resource": "arn:aws:sagemaker:<REGION>:<ACCOUNT_ID>:endpoint/<ENDPOINT_NAME>"
        },
        {
            "Effect": "Allow",
            "Action": "sagemaker:CallWithBearerToken",
            "Resource": "*"
        }
    ]
}

ステップ 3: ベアラートークンの生成

from sagemaker.core.token_generator import generate_token
from datetime import timedelta

# デフォルトは 12 時間有効。expiry で上書き可能（1 秒〜12 時間）
token = generate_token(region="ap-northeast-1", expiry=timedelta(minutes=5))

長時間稼働するアプリケーションには、リクエストごとに新しいトークンを自動生成する httpx.Auth パターンが推奨されます。

import httpx
from sagemaker.core.token_generator import generate_token

class SageMakerAuth(httpx.Auth):
    def __init__(self, region: str):
        self.region = region

    def auth_flow(self, request):
        request.headers["Authorization"] = f"Bearer {generate_token(region=self.region)}"
        yield request

http_client = httpx.Client(auth=SageMakerAuth(region="ap-northeast-1"))

ステップ 4-A: 単一モデルエンドポイントを OpenAI SDK で呼び出す

from openai import OpenAI
from sagemaker.core.token_generator import generate_token

REGION = "ap-northeast-1"
ENDPOINT_NAME = "<your-endpoint-name>"

client = OpenAI(
    base_url=f"https://runtime.sagemaker.{REGION}.amazonaws.com/endpoints/{ENDPOINT_NAME}/openai/v1",
    api_key=generate_token(region=REGION),
)

# ストリーミング呼び出しの例
stream = client.chat.completions.create(
    model="",   # SageMaker はエンドポイント名で routing するため空でも可
    messages=[
        {"role": "system", "content": "You are a helpful assistant."},
        {"role": "user", "content": "トランスフォーマーの仕組みを3文で説明してください。"},
    ],
    stream=True,
)
for chunk in stream:
    if chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="")

ステップ 4-B: 推論コンポーネント（複数モデルホスティング）を呼び出す

from openai import OpenAI
from sagemaker.core.token_generator import generate_token
import httpx

REGION = "ap-northeast-1"
IC_ENDPOINT_NAME = "<your-ic-endpoint-name>"
IC_NAME = "<your-inference-component-name>"

shared_http = httpx.Client()   # 複数クライアントで TLS セッションを共用

client = OpenAI(
    base_url=(
        f"https://runtime.sagemaker.{REGION}.amazonaws.com"
        f"/endpoints/{IC_ENDPOINT_NAME}/inference-components/{IC_NAME}/openai/v1"
    ),
    api_key=generate_token(region=REGION),
    http_client=shared_http,
)

response = client.chat.completions.create(
    model="",
    messages=[{"role": "user", "content": "42 × 3 は？"}],
)
print(response.choices[0].message.content)

ステップ 4-C: Strands Agents との統合

SageMaker エンドポイントをバックエンドに使ったエージェントをそのまま構築できます。

from openai import AsyncOpenAI
from strands import Agent, tool
from strands.models.openai import OpenAIModel
from sagemaker.core.token_generator import generate_token

REGION = "ap-northeast-1"
ENDPOINT_NAME = "<your-endpoint-name>"

@tool
def calculator(expression: str) -> str:
    """数式を評価して結果を返す"""
    return str(eval(expression))

strands_client = AsyncOpenAI(
    base_url=f"https://runtime.sagemaker.{REGION}.amazonaws.com/endpoints/{ENDPOINT_NAME}/openai/v1",
    api_key=generate_token(region=REGION),
)

model = OpenAIModel(client=strands_client, model_id="", params={"temperature": 0.7})

agent = Agent(
    model=model,
    system_prompt="You are a helpful assistant.",
    tools=[calculator],
)

使い終わったらリソースを削除する

SageMaker AI エンドポイントはサービス中は継続して課金されます。不要になったら必ず削除してください。

import boto3
sagemaker_client = boto3.client("sagemaker", region_name="ap-northeast-1")

sagemaker_client.delete_inference_component(InferenceComponentName="<IC_NAME>")
sagemaker_client.delete_endpoint(EndpointName="<ENDPOINT_NAME>")
sagemaker_client.delete_endpoint_config(EndpointConfigName="<ENDPOINT_CONFIG_NAME>")
sagemaker_client.delete_model(ModelName="<MODEL_NAME>")

注意点

💰 エンドポイントの課金

SageMaker AI エンドポイントは、InService 状態である限りトラフィックの有無にかかわらず料金が発生します。検証・テスト後は速やかに推論コンポーネント→エンドポイント→エンドポイント設定→モデルの順に削除してください。

🔐 ベアラートークンのセキュリティ

ベアラートークンは生成に使用した AWS 認証情報と同等の権限を保持します。以下の点に注意してください。

  • 保存禁止: ディスク・環境変数・設定ファイル・データベース・分散キャッシュへの保存を避ける
  • ログ出力禁止: トークン文字列をログに記録しない
  • 送信は HTTPS のみ: 暗号化された通信経路でのみ送信する
  • 使用時に生成: トークン生成はネットワーク呼び出しが不要なローカル処理のため、保存せず使用直前に毎回生成するか、httpx.Auth の自動更新パターンを利用する
  • 有効期限を最短に: ワークロードが必要とする最短の expiry を設定する

🔒 IAM ポリシーのスコープを最小化する

  • sagemaker:InvokeEndpoint は呼び出すエンドポイントの ARN のみに制限する（ワイルドカード * は使用しない）
  • AdministratorAccess や AmazonSageMakerFullAccess のような広範なポリシーを持つロールからはトークンを生成しない
  • sagemaker:CallWithBearerToken はリソースレベルの制限をサポートしていないため、Resource: "*" の指定が必須となる（これは仕様上の制約）

⚙️ model フィールドの扱い

SageMaker はリクエストの routing を URL 内のエンドポイント名で行います。そのため model フィールドはコンテナがそのまま受け取るパラメータであり、空文字列（""）のままか、コンテナが期待するモデル名を設定します。OpenAI API の厳密な model 検証は行われません。

📦 対応コンテナの要件

OpenAI 互換 API を利用するには、コンテナが /v1/chat/completions パスと SSE 形式のストリーミングレスポンス、および /ping ヘルスチェックエンドポイントを実装している必要があります。SageMaker の標準 vLLM・SGLang DLC はすべて対応済みです。
