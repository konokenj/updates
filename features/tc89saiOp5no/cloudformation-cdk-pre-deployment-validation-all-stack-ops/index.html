AWS CloudFormation・CDK、CreateStack/UpdateStack操作にデプロイ前検証を追加——エラーを秒単位で検出

FEAT AWS What's New · 2026/6/30
要約: CloudFormationのCreateStack・UpdateStack操作にデプロイ前検証がデフォルト有効化。プロビジョニング前にプロパティ構文エラーやリソース名競合を秒単位で検出し、ロールバック待ちを排除。CI/CDや全デプロイワークフローで設定不要。CDKはコンストラクトレベルの統合レポートにも対応。

新機能の背景

CloudFormation でスタックをデプロイする際、テンプレートのプロパティ構文ミスやリソース名の競合といった「防げるはずの失敗」を検出するには、従来はリソースのプロビジョニングが始まってから失敗し、ロールバックが完了するまで待つ必要がありました。このサイクルには数分〜数十分かかることもあり、開発者の反復速度を著しく低下させていました。

デプロイ前検証（Pre-deployment validation）自体はすでに Change Set 作成時 には利用可能でしたが、CreateStack や UpdateStack を直接呼び出すワークフロー（CI/CD パイプライン、AI エージェントによる自動プロビジョニング、手動デプロイなど）ではこの恩恵を受けられませんでした。

今回のアップデートにより、すべてのスタック操作 に対してデプロイ前検証が自動的に実行されるようになり、エラーを秒単位で検出できるようになりました。

新機能の概要

① CreateStack / UpdateStack へのデプロイ前検証の拡張

CreateStack および UpdateStack の操作に対して、デフォルトで自動的にデプロイ前検証が実行されるようになりました。検証でエラーが検出された場合、リソースのプロビジョニングが開始される前に操作が停止し、スタックのステータスに検証失敗が反映されます。

以下の 2 種類の検証が CreateStack・UpdateStack・CreateChangeSet のすべてで FAIL モード（エラー時は操作停止）で動作します：

検証の種類 内容
プロパティ構文検証 AWS リソーススキーマに対してリソースプロパティを検証。必須プロパティの欠如、無効な値、非推奨のプロパティ組み合わせを検出
リソース名競合検出 既存 AWS リソースとの名前衝突、AWS の命名要件違反を検出

② Change Set 作成時の新しい 3 つの WARN モード検証

Change Set 作成時のみ動作する追加検証として、以下の 3 種類が新たに追加されました。WARN モードのため Change Set 作成は成功しますが、警告として開発者に通知されます：

検証の種類 内容
サービスクォータ検証 リソースの作成によりアカウントのサービスクォータを超過しないかを確認
Config Recorder 競合検出 Config 記録が有効でないアカウントへの Config ルール追加、または既に Config Recorder が存在するアカウントへの Recorder 定義を検出
ECR リポジトリ削除準備状況検証 削除対象の ECR リポジトリにイメージが残っている場合に警告

なお、S3 バケット空チェック（削除対象のバケットにオブジェクトが存在する場合の警告）も引き続き Change Set 作成時のみ WARN モードで動作します。

③ CDK との統合

AWS CDK では cdk deploy および cdk validate コマンドの両方で検証結果がコンストラクトレベルのトレース情報とともに 統合レポートとして出力されます。構造化されたレスポンスにより、AI エージェントや自動化ツールが即座に結果を解析し自己修正できるようになっています。

検証結果の確認方法

各検証エラーには 論理リソース ID とプロパティパスが含まれるため、テンプレートのどこに問題があるかを正確に特定できます。

  • コンソール: スタックの「イベント」タブからオペレーション ID をクリック →「オペレーション」ビューの「デプロイ検証」タブで詳細を確認
  • AWS CLI: describe-events コマンドにオペレーション ID を指定して確認
# スタック作成（検証は自動で実行される）
aws cloudformation create-stack \
  --stack-name MyStack \
  --template-body file://template.yaml

# スタック更新（検証は自動で実行される）
aws cloudformation update-stack \
  --stack-name MyStack \
  --template-body file://updated-template.yaml

# 検証結果の確認
aws cloudformation describe-events \
  --stack-name MyStack

使い方

デプロイ前検証は設定不要でデフォルト有効です。追加のコマンドや設定変更は一切必要ありません。既存の create-stack / update-stack ワークフローがそのまま恩恵を受けます。

検証をスキップしたい場合

特定の操作で検証をスキップする必要がある場合は、DisableValidation パラメータ（API）または --disable-validation フラグ（CLI）を使用します：

# 検証を無効化してスタック作成
aws cloudformation create-stack \
  --stack-name MyStack \
  --template-body file://template.yaml \
  --disable-validation

# 検証を無効化してスタック更新
aws cloudformation update-stack \
  --stack-name MyStack \
  --template-body file://template.yaml \
  --disable-validation

検証スキップが適切なケースの例：

  • cfn-lint、cdk validate、CI チェックなど他の手段で既に検証済みの場合
  • 時間的に重要なデプロイでレイテンシを最小化したい場合
  • 既知の誤検知（false positive）がブロックしている場合

必要な IAM 権限（Change Set 作成時の追加検証用）

Change Set 作成時の WARN モード検証を利用するには、通常の CloudFormation 権限に加えて以下の権限が必要です：

検証 必要な権限
サービスクォータチェック cloudwatch:GetMetricData, lambda:GetAccountSettings, servicequotas:GetServiceQuota, ec2:DescribeSecurityGroups, iam:GetAccountSummary
Config Recorder 競合チェック config:ListConfigurationRecorders
S3 バケット空チェック / ECR リポジトリチェック s3:ListBucketV2, ecr:ListImages

利用可能リージョン

中国リージョンを除く、CloudFormation がサポートされているすべての AWS リージョンで利用可能です。

注意点

デプロイ成功を保証するものではない

デプロイ前検証は一般的な失敗パターンを事前に検出するものであり、デプロイが必ず成功することを保証するものではありません。カスタムリソースのロジックやサービス固有の実行時制約による失敗は、引き続きプロビジョニング中に発生する可能性があります。

一部のリソースタイプは検証対象外

多数の CloudFormation リソースタイプはデプロイ前検証に対応していません（AWS::CloudFormation::CustomResource、AWS::ECR::Repository、AWS::Lambda::EventSourceMapping など多数）。これらのリソースを含むテンプレートでは、プロパティ構文検証やリソース名競合検出が実行されない場合があります。完全なサポート対象外リソース一覧はユーザーガイドを参照してください。

CreateStack / UpdateStack では WARN モード検証は動作しない

S3 バケット空チェック、サービスクォータ検証、Config Recorder 競合検出、ECR リポジトリ削除準備状況検証の 4 種類は、Change Set 作成時のみ動作します。CreateStack / UpdateStack を直接呼び出すワークフローではこれらの警告は得られません。これらも検証したい場合は、Change Set を経由するデプロイフローを採用することを検討してください。

わずかなレイテンシの増加

CreateStack および UpdateStack 操作に対して検証が実行される分、数秒程度のレイテンシが追加されます。レイテンシを最小化したい場合は --disable-validation フラグで検証をスキップできます。

S3 バケット検証の制限

S3 バケット空チェックはバケット内のオブジェクトの有無のみを確認します。バケットポリシーや削除を妨げる他の制約については検証されません。
